Milestone 4 · BRE-229

One calm stream, many mailboxes.

The unified inbox contract makes provider and account provenance explicit without making either one the user's primary navigation model.

Response shape

  • accounts[] is the set of connected mailboxes visible to the user.
  • messages[] is one stream sorted across accounts.
  • Every message keeps both accountId and provider.
  • Counts describe the returned unified set, not one provider.

Thread identity

A thread read is always scoped by the pair (accountId, threadId). The account is not inferred from a global thread id or the current mailbox.

This prevents two providers—or two Gmail accounts—from accidentally resolving the same-looking provider thread in the wrong account.

Example

{
  "accounts": [
    { "id": "acct_gmail", "provider": "gmail", "email": "maya@example.com", "displayName": "Maya Gmail", "capabilities": { "read": true, "draft": false, "send": false } },
    { "id": "acct_outlook", "provider": "outlook", "email": "maya@work.example", "displayName": "Maya Work", "capabilities": { "read": true, "draft": false, "send": false } }
  ],
  "messages": [
    {
      "id": "gmail:acct_gmail:msg_42",
      "accountId": "acct_gmail",
      "provider": "gmail",
      "threadId": "gmail:acct_gmail:thread_7",
      "receivedAt": "2026-08-09T17:30:00.000Z"
    }
  ],
  "counts": { "focus": 0, "normal": 1, "quiet": 0, "hidden": 0, "all": 1 },
  "nextCursor": null
}

Ordering

The unified implementation uses descending receivedAt across every account. Equal timestamps use ascending local message id as the deterministic tie-breaker.

Human Signal / Tideline

Human Signal remains a property of each message. Future Tideline or human-mail filtering must classify and explain results per message, never infer a provider-wide or account-wide score.
