01

Locked decisions

These are approved. Implementation work applies them consistently rather than reopening them screen by screen.

NavigationOne integrated sidebar

The permanent icon rail is removed. Compose, anchors, workflow spaces, Organization, Settings, and account health live in one column. Search stays in the workspace header.

Light identityWordmark + secondary wave

The Orca wordmark leads. The wave sits beside it as a compact secondary icon.

Dark identityOrca Black + original Orca icon

Pure black and graphite carry the theme. The asymmetric “o” tile from the first atlas is retained exactly. White is decisive; blue is a minor functional highlight.

Information architectureAnchors versus spaces

Inbox and Drafts remain stable. Focus, Signals, Quiet, Later, and custom spaces are user-shaped. Organization and Settings are stable workspace controls.

EvidenceHuman Signal is explanatory

Human Signal may rank or explain a placement. It never becomes a permanent Human versus Automated navigation split.

OrganizationBRE-307 Glass Box remains authoritative

When → If → Then → Because, Tide Table, simulation, Trace/Audit, authority gates, activation, and compensating revert retain their approved semantics.

WritingSimple reply first, Zen on demand

Inline reply is the fastest start. Full composer and Zen preserve draft, recipient, send, recovery, and return context.

SettingsComplete product surface

Account, Appearance & Reading, Inbox & Attention, Writing, Notifications, Connected Accounts, Agent Connections, and Privacy & Data are all first-class.

Execution sequence

Each step has an exhaustive, observable completion criterion. Do not move ahead with partial route coverage.

Extract shared tokens and theme identities

Create semantic variables for paper, surface, hover, ink, muted, borders, accent, warnings, danger, rule pieces, spacing, radii, type, and motion. Define Light and Orca Black separately.

Complete when: every atlas color is represented by a semantic token; no selected control depends on guessed inverse colors; both theme token sets pass contrast review.

Build the integrated shell

Replace the persistent icon rail with the approved sidebar. Add wordmark/brand icon, Compose with icon and shortcut, anchors, spaces, workspace controls, account health, top search, and narrow management drawer.

Complete when: every shell route uses one sidebar; Compose and Search remain keyboard-reachable; the sidebar supports all required destinations and a 1024px layout.

Unify message list and evidence primitives

Implement the fixed-column message row, selection toolbar, “why here” slot, time/action slot, empty/loading/offline states, and contextual evidence drawer.

Complete when: Inbox, spaces, Search, All Mail, and Drafts share aligned row geometry across light, dark, unread, selected, loading, and disabled states.

Move every reading and writing surface

Apply the reader, inline reply, composer, send failure, discard confirmation, Draft conflict, Zen, interruption recovery, and safe return behaviors.

Complete when: triage → read → reply → send returns to the exact list context; every interruption preserves content and exposes the next safe action.

Connect Organization to the new shell

Keep the approved Glass Box and Tide Table internals; update only the surrounding shell, workflow-space terminology, and evidence entry points.

Complete when: discovery, simulation, activation, explanation, Audit, and compensating revert run as one traceable journey without changing BRE-307 authority semantics.

Complete Settings and provider recovery

Implement all eight settings areas and their Gmail, Outlook, label, calendar, agent, privacy, permission, and onboarding branches.

Complete when: every Settings route and state in the inventory is reachable from Settings home, names its save scope, and has loading/error/permission/revoke behavior.

Verify every route, theme, state, and journey

Run automated checks and capture reviewer evidence in both themes and at narrow desktop width.

Complete when: every inventory row is checked, all six journeys pass, default/hover/focus/selected/disabled controls remain labeled, and reviewer screenshots cover each major flow.
03

Brand and theme system

Light and dark share structure but have distinct identities. Theme switching changes tokens and brand icon, not content hierarchy.

Light · Tidal control room

  • Primary mark: lowercase Orca wordmark.
  • Secondary icon: wave inside a small rounded icon container.
  • Atmosphere: foam paper, white surfaces, ink text, lagoon accent.
  • Primary action: lagoon Compose button.
  • Selected state: surfaced background + visible border + ink label.

Dark · Orca Black

  • Primary mark: same wordmark.
  • Secondary icon: original asymmetric rounded “o” tile from the first atlas. Treat it as a fixed asset; do not redraw its geometry.
  • Atmosphere: pure black, near-black graphite, warm white.
  • Primary action: warm-white Compose button with black label.
  • Blue: active edge, status dot, Focus marker, evidence label only.

Typography

Newsreader carries reading, headings, and the human voice. Sora carries controls and navigation. System mono carries shortcuts, counts, queries, rules, and audit data. Reader settings may change message text size without resizing navigation.

Shape and spacing

Use 8/10/12px control radii, 14/16px card radii, 18/22px major-surface radii, and 999px only for chips. Use a 4px spacing base with 8, 12, 16, 20, 24, 32, 40, and 48px steps. Repeated rows use explicit grid columns rather than free gaps.

Six acceptance journeys

Screen-level polish does not count if context breaks between screens.

01 · Triage → read → reply → return

Inbox item + list cursor→Reader + evidence→Inline/full reply→Sent→Same list item and position

02 · Create and manage a workflow space

Manage spaces→Create / rename / reorder→Organize message→Hide space→Restore with rules intact

03 · Organization discovery → change → accountability

Why here?→Glass Box / Tide Table→Simulate + authority→Activate + Trace→Compensating revert

04 · Draft → Zen → interruption → send

Composer draft→Zen→Crash / close→Recover / compare→Send + return

05 · Connect or repair an account

Settings home→Permission preview→Provider failure→Boundary explanation→Retry / connected

06 · Offline editing → reconciliation

Online edit→Offline named→Local save→Reconnect→Deduplicate / conflict compare

Accessibility and theme safety

A control without a readable label in any state is a release blocker.

Keyboard and semantics

  • All navigation, Compose, Search, row selection, drawers, rule pieces, settings, dialogs, and Zen actions are keyboard reachable.
  • Use landmarks, heading order, accessible names, aria-current, aria-pressed, aria-expanded, aria-busy, live regions, and dialog focus management.
  • C opens Compose outside text entry; ⌘K opens Search; Esc closes the current transient layer; shortcut help remains discoverable.

Visual access

  • Body text and controls meet WCAG AA contrast; small metadata is never the only carrier of meaning.
  • Focus is visible in Light and Orca Black without relying on color alone.
  • Selected states keep labels visible using the established surface + border + ink treatment.
  • Reduced motion removes reveal, pulse, and transform effects while preserving state changes.
  • Large reader text changes message content without breaking message headers or controls.
Theme-safe selected-state rule: never pair background: var(--orca-ink) with an assumed inverse variable. Use semantic selected tokens and verify default, hover, focus, pressed, and disabled states in both themes.

12

Definition of done

The switch is complete only when every statement below is observable in the running product and reviewer evidence.

Release gate

  1. All production desktop routes in the inventory use the integrated one-sidebar shell or an intentional full-screen exception such as Zen.
  2. Light and Orca Black match the approved brand roles and semantic tokens.
  3. All 27 atlas frames have an implemented route or state mapping.
  4. Every Settings area and integration branch is reachable, scoped, and recoverable.
  5. All shared operational states use the same preservation-and-next-action grammar.
  6. All six acceptance journeys pass without losing content, intent, evidence, or return position.
  7. Typecheck, tests, build, and lint pass.
  8. Visual evidence covers both themes, narrow desktop, required control states, and every major flow.
  9. No release-blocking contrast, unlabeled selection, inaccessible dialog, draft-loss, authority, or permission-boundary defect remains.
Document maintenance: update this specification when the approved UI model changes. Update the atlas for visual changes. Keep route behavior and token definitions single-sourced in code; this document records decisions, mappings, completion criteria, and implementation constraints.
