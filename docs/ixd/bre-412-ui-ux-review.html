Three actions that need distinct meaning

People need to understand what will change before they separate their mail. The current model has useful foundations, but the routes and labels make those distinctions harder to discover.

Move to a space

Choose the primary place for a conversation. Sender choices can also route existing and future mail.

Include in a view

Change live matching rules. A conversation can match several views; adding a sender must preserve the other rules.

Keep out of Inbox

An explicit view policy hides matching mail from Orca Inbox. It does not archive provider mail or delete the conversation.

Hiding a sidebar shortcut is a device preference. It must not quietly alter the view’s matching rules or Inbox policy.

Add selected senders to an existing saved view with an explicit matching-mail preview

Selected mail can create a new sender view, but cannot extend an established view. The missing action forces users to rebuild or manually edit a filter.

Acceptance criteria & ownership
Observed: Inbox → Select → select mail → Use these senders only creates a new view. Saved-view results offer Edit and Correct senders but no discoverable add flow. User explicitly requested adding more mail to an established view.

Acceptance:

* Selection offers a clear choice to create a sender view or add selected senders to an existing saved view. Saved-view page exposes a discoverable Add senders path.
* Use authoritative selected-message preparation; never infer a topic or treat a live view as a folder. Display exact sender addresses and account scope, including omitted self-senders.
* Adding senders must widen the sender set with deduplication and preserve unrelated filters, identity/color/order, skipInbox policy, and revisions. Explain that other filters still apply. Do not silently constrain a view without sender filters or expand account scope: present explicit reviewed changes or a clearly explained supported-path alternative.
* Show current→proposed change and matching-mail preview; no mutation until explicit save; cancel preserves source selection and view; stale/permission/failure states preserve the draft.
* Reuse existing prepare/preview/commit authority and idempotency flow; meaningful API/UI tests for duplicate addresses, account scope, domain semantics, conflicts, skipInbox preservation.
  Ownership: new growth modules plus App.tsx integration and required view/API/shared seams. Coordinate overlapping organization-views edits in later waves.
