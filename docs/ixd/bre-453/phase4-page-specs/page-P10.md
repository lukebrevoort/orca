# P10 — Advanced Organization

## 1. Overview
Retain existing expert organization, rules and evidence behind a discoverable Advanced Organization entry. Entry: P02/P09 Organize or supported legacy link; exit: origin, saved-view results or contextual reader. Covers D5, NAV-01/03 and CORE-03. This preservation spec does not authorize rebuilding existing advanced editors or converting their rules into importance.

## 2. Layout
Web shell → account/workspace identity and mode → existing rules/lanes/editor → contextual simulation/evidence → owned save/apply/revert status. Preserve useful existing disclosure and split-pane behavior; narrow web stacks panels with explicit navigation. Routine triage does not require this workspace.

## 3. Components
Existing rule/lane/space/view editors; explicit matching/action summaries; Glass Box/Tide Table; simulation; apply/revert; revision/conflict/authority recovery; trace/audit details; unsaved guards. Each operation retains its established consequence and security boundary; importance is a separate contract.

## 4. Behavior
Reuse current editing, simulation, apply/revert and evidence workflows. A simulation is read-only and must not imply applied provider effects. Mutating actions require their existing explicit target/scope/revision protections and truthful result evidence. Revert is limited to the real supported operation/revision; it is not a general undo history. Ordinary view previews remain P08's zero-write flow; preserve legacy explicit advanced policies without silently enabling them.

## 5. State machine
Owned load → ready/editing/simulating → current preview or stale/error → guarded saving/applying/reverting → acknowledged result/conflict/partial or recoverable failure as supported. Editing invalidates stale simulations. Ambiguous mutation reconciles authority before replay; repeated actions cannot widen scope. Dirty exit uses the existing top-layer guard. Session/account revocation removes inaccessible evidence and rejects delayed callbacks.

## 6. Motion
Use established editor/disclosure tokens and reduced motion. Panel changes preserve focus and relevant editor position; no decorative animation competes with evidence. Pending/error status remains visible throughout long operations and does not cover action controls.

## 7. Data loading
Preserve existing shared schemas, revision guards, simulation/trace pagination, ownership and rollback contracts. Bound work and expose partial evidence rather than invent complete counts. Existing routing remains routing; neither Human Signal nor provider destination becomes importance by relabeling. Do not add provider writes during explanation or preview.

## 8. Adaptation
This advanced workspace is web-only in the current inventory. Responsive web must keep editor/evidence/actions accessible at narrow widths and zoom; it does not establish native iOS parity. Native keeps supported simple view/mailbox journeys and truthful availability guidance rather than a nonworking editor. Both themes retain readable selected, disabled and focus states.

## 9. Walkthrough
Existing rule/lane/Glass Box/Tide Table workflows; simulate without writes → explicit apply → actual supported revert; changed input/owner while pending; stale revisions; partial failures; dirty navigation; repeated operations and authority recovery. Compare independent state/provider calls and contextual trace. Inspect light/dark and narrow/desktop feedback collisions. Full existing relevant suites and independent security/correctness review remain required, not claimed run here.

## 10. Micro-interactions
Summaries state exactly what matches and which effects are proposed/applied. Evidence links keep return context. Pending controls identify owned work; stale preview asks for fresh simulation rather than presenting misleading success. Optional detail never displaces the safe exit or recovery route.
