Orca · M6 · BRE-263 · Contract v1

Important machine mail becomes a small, explainable event.

Agent Propagation is a provider-neutral, account-owned projection. It never changes Human Signal, sender attention, provider labels, or provider state.

Final vocabulary: four independent decisions

Human ClassificationHow the source appears to have been produced.
Attention BehaviorThe user’s sender placement: Notify, Focus, Normal, Quiet, or Hidden.
Agent ImportanceThe likely consequence of this event for this user: high, medium, low, or unknown.
Propagation DestinationTimeline, Focus, Notify, future Agent View, or none.

Automated does not mean unsafe, spam, or unimportant. Propagated does not move the source out of Tideline. No field may be derived from another as a shortcut.

Retry-safe identity and update algorithm

  1. Serialize the exact UTF-8 JSON array ["agent-event-dedupe-v1", ownerUserId, accountId, provider, providerMessageId, eventKind, policyVersion] with no whitespace.
  2. Set deduplicationKey to sha256: plus its lowercase SHA-256 hex digest. Insert under unique (owner_user_id, account_id, deduplication_key).
  3. Compute a second SHA-256 assessment_fingerprint from the bounded, persisted meaning fields, excluding trigger, evaluation time, lifecycle, and database timestamps.
  4. On conflict: equal fingerprint is a strict no-op; changed fingerprint updates bounded fields, increments revision once, and sets lastTransition=updated. Preserve seen/dismissed/snoozed/muted/false-positive state.
  5. Invalidation increments once and retracts. Repeated retraction is a no-op. Never resurrect a retracted event automatically.

Immutable source rule: a new provider message—even in the same thread—gets a new key and event. It may explicitly retract a prior event, but never replaces that event’s source identity. This avoids hidden source swapping and makes retries deterministic.

Every user mutation carries expectedRevision. A mismatch is HTTP 409 with the current event/revision. Successful transitions increment once; exact repeats are idempotent.

Account isolation

  • Composite foreign keys prove owner ↔ account ↔ thread ↔ message membership.
  • All list/update queries begin with authenticated owner and allowed account IDs.
  • Identical provider IDs in two connected accounts remain distinct.
  • A deep link is a locator, never authorization; re-authorize it on open.

Conservative policy

CategoryDefault eligibility
Release/TestFlight; CI/deploy failure; security/account alert; receipt/renewal; travel/booking changeOn, but only with sufficient deterministic evidence
Marketing/newsletter; other/unknownOff

Account-scoped sparse overrides opt any category in or out. Mutes target a sender address, sender domain, or event kind and are reversed by deleting the mute. Eligibility is not unconditional propagation.

Privacy and read-only boundary

  • Persist bounded title (160), summary/why (500), next step (300), source identity, and Human Classification snapshot—never body HTML/text, headers, or attachments.
  • Logs contain event/account IDs, versions, reason codes, transition, latency, and fingerprints. Redact sender, subject, summaries, URLs, bodies, tokens, cookies, and authorization values.
  • Agent responses treat all mail-derived text as untrusted, redact secrets, bound lengths, strip source URL query/fragment, and omit owner/dedupe internals.
  • No archive, delete, relabel, send, draft, provider mark-read, or other provider write is authorized.

Deterministic now, model-assisted later

M6 emits executionMode=deterministic. A future model-assisted evaluator must emit the identical Zod wire shape, retain policy/agent versions, obey the same privacy limits, and pass through the same idempotent store. It cannot redefine Human Signal.
