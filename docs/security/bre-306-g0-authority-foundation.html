Persistent organization authority starts fail-closed.

One deep Organization module owns authority for humans, agents, and system processes. REST, MCP, provider sync, and background work are adapters; none may recreate policy.

Eligibility only permits evaluation. The immutable Capability Snapshot must still grant the operation, Workspace, Accounts, resource families, and action families.

Authority decision

1 · Identity

Actor ID and type must match an exact current, non-revoked Capability Snapshot.

2 · Runtime boundary

Malformed requests or live authority inputs deny with stable validation codes instead of throwing or trusting erased types.

3 · Live scope

Requested Workspace and every Account must exist in both live ownership and the grant. No silent narrowing.

4 · Derived authority

The exact typed command—including create/update lifecycle and changed values—determines resources, actions, target IDs, and risk.

5 · Hard exclusion

Mail send, provider deletion, and destructive risk are impossible under M8 Organization authority.

6 · Write safety

Updates require equal live/expected revisions; creates require nonexistence. Previously reserved idempotency keys deny.

7 · Bound execution

An allow returns a SHA-256 command digest and preconditions that the mutation transaction must recheck and reserve atomically.

8 · Complete Trace

Allow and deny preserve the digest, requested families and IDs, Actor, grant, scope, revisions, derived risk, winner, and reason.
