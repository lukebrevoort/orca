# Keep authority inside the five-operation Organization seam

Orca will expose `describe`, `query`, `simulate`, `apply`, and `revert` as the complete Organization interface instead of spreading per-resource authorization through REST, MCP, sync, and background callers. Every adapter supplies an explicit Actor, a claimed immutable Capability Snapshot, Workspace and Account scope, an exact typed command, and expected revisions. Mutation intents explicitly distinguish create from update and carry their typed changed values. The deep Organization module validates those values at runtime, derives resource families, action families, and risk from the command, intersects the request with live ownership, and requires an exact current, non-revoked Capability revision. It returns an auditable Trace plus an execution context bound to a canonical digest of the full command. Updates require equal live and expected revisions; creates require explicit nonexistence. The eventual mutation transaction must atomically reserve that context's idempotency key and recheck its revisions. This concentrates account isolation, stale-grant defense, replay preconditions, and denial behavior in one test surface, while keeping mail send and provider deletion outside M8 authority.
