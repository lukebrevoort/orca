Orca · BRE-299 / BRE-290

Drafts are durable. Inbox switching is lighter.

This page explains what changed and what “faster” means here. The implementation has strong request-path improvements, but this work did not capture a before/after stopwatch benchmark, so there is no defensible exact millisecond claim.

Short answer: classification switching no longer starts a Gmail sync, and a Compose close no longer refetches collections, pins, reminders, and view settings. The exact time saved depends on network and Gmail latency; the largest avoided cost is one full sync cycle per classification switch in the old flow.

How much faster?

1 fewer sync cycle

After the initial load, changing Human / Tideline / Uncertain / All only reads the requested inbox view. It does not POST to /v1/sync/gmail.

The saved time is roughly the old Gmail sync duration plus its follow-up reads. That may be hundreds of milliseconds or several seconds, depending on the account and network.

4 fewer requests

Closing Compose refreshes drafts independently. It no longer re-fetches collections, pins, reminders, and reminder view settings.

This is an exact request-count reduction per close, excluding any requests made by the user’s next action.

1 source of truth

The main composer receives the App-owned draft list instead of requesting /v1/drafts again.

That removes duplicate draft-list work and prevents the mailbox and composer from hydrating from different snapshots.

What I implemented

Cached inbox renders→Gmail refresh runs independently→Latest classification is re-read until stable
  • Added the Drafts mailbox and durable draft reopening.
  • Scoped composer hydration, autosave queues, target IDs, and revisions to the active draft scope.
  • Preserved server attachments during text edits and merged them with newly added local files for autosave and send.
  • Separated draft loading from collections, pins, reminders, and view settings, with loading, error, retry, and empty states.
  • Kept Refresh disabled through the entire background sync/read lifecycle.
  • Restored keyboard focus to the draft row that opened Compose.

Evidence

Verification during this work included full workspace typechecking, a production build, and a full test-suite run with 416 tests passed. After the final refresh-loop and type-narrowing changes, typecheck, build, and the focused App and interaction suites passed 80 tests, including mounted scope transitions, deferred saves, attachment merging, repeated classification switches, and focus restoration.

For a true “X ms faster” claim, the next step would be a repeatable browser benchmark against the same seeded mailbox and network conditions, measuring time to first visible inbox rows, classification-switch completion, and Compose-close settling.
