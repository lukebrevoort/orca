Outbound delivery contract

A provider-neutral draft is the shared boundary between Orca’s writing experience and a mail provider. The draft is safe to persist locally before Gmail is allowed to accept anything.

Authority by phase

Writingmessage_drafts content, revision, and timestampsNone

Draft lifecycle

  1. POST /v1/drafts creates an account-owned draft at revision 0.
  2. PATCH /v1/drafts/:id requires that revision; a mismatch returns stale_draft (409) and the current revision.
  3. GET /v1/drafts and GET /v1/drafts/:id reload only drafts belonging to the authenticated account.
  4. DELETE /v1/drafts/:id discards the local draft.

Delivery safety

Every send command carries an idempotencyKey. Before a future Gmail transport makes a network call, it must atomically reserve that key on this draft and set deliveryStatus to sending. A retry with the same key returns the stored result; a different key while delivery is in flight or uncertain returns ambiguous_delivery. The current read-only Gmail connection deliberately returns missing_capability and makes no delivery attempt.

Normalized errors are validation_error, stale_draft, missing_capability, provider_rejected, ambiguous_delivery, and attachment_limit. Routine logs must never include recipient or body payloads.
