Orca M5 · BRE-247

Human Signal is an explainable estimate, never a verdict.

This is the provider-neutral contract for separating likely human messages from automated or bulk mail. It gives people the final say, keeps Orca’s reasoning inspectable, and deliberately does not claim to detect AI-written text, identity, safety, or intent.

Product promise Orca can say Likely human, Automated or bulk, Uncertain, or Unclassified. It must not say “definitely human,” “AI-written,” “safe,” or imply that a provider label proves authorship. Classification does not change a provider mailbox and is independent of attention, read state, stars, labels, and account/provider identity.

Canonical wire model

The legacy nullable humanSignal stays for compatibility. New clients use humanClassification.effective; a raw score alone is never a filter policy.

{
  "humanSignal": 8,
  "humanClassification": {
    "automatic": {
      "classification": "likely_human",
      "score": 8,
      "reasonCodes": ["direct_recipient", "reply_context"],
      "classifierVersion": "m5-v1"
    },
    "effective": {
      "classification": "likely_human",
      "score": 8,
      "reasonCodes": ["direct_recipient", "reply_context"],
      "classifierVersion": "m5-v1",
      "source": "automatic_heuristic"
    }
  }
}

What consumers use

  • effective.classification drives Human Inbox, Tideline, and Review views.
  • effective.source tells the UI whether Orca estimated it or the user chose it.
  • automatic remains intact after a correction so reset-to-automatic is honest and reversible.
  • reasonCodes are stable, user-safe evidence labels—never raw header values or message contents.
  • humanSignal mirrors the effective score when one exists; it is nullable and must not be thresholded by a client.

Classification bands

Internal valueUser-facing copyScore conventionMeaning
likely_humanLikely humanUsually 7–10Evidence such as a direct recipient relationship or reply context supports ordinary person-to-person correspondence. It remains an estimate.
automated_or_bulkAutomated or bulkUsually 0–3Transparent delivery, list, subscription, transactional, or automation metadata outweighs human correspondence evidence.
uncertainUncertainUsually 4–6 or nullEvidence is weak or conflicts. Orca intentionally leaves this for review rather than forcing it into Tideline.
unclassifiedUnclassifiednullThere is not enough stored evidence yet—for example, a historical row that predates normalized evidence/backfill.

The classifier selects a band from all evidence. The numeric ranges are conventions for explainability, not a license for a client to reproduce policy with a magic threshold.

Evidence boundary

Provider adapters reduce Gmail and Outlook data to HumanClassificationEvidence before the deterministic classifier runs. The classifier is pure and may inspect only the normalized facts below.

Gmail / OutlookHeaders, labels/categories, contacts, reply metadata
Normalized evidenceSender, recipients, directness, reply context, header and provider signals
Deterministic rulesBounded score, class, stable reasons, version
Effective resultAutomatic estimate or a local user correction

Allowed header signals are List-Id, List-Unsubscribe, Precedence, Auto-Submitted, and X-Auto-Response-Suppress, normalized to enum values. Gmail labelIds and Outlook categories are mapped to provider-neutral signals before scoring. The classifier must not inspect message body text, upload content, call a network service, train from corrections, or infer AI authorship.

Override precedence

A correction is local to Orca and account-scoped. It does not archive, delete, label, categorize, or otherwise mutate Gmail or Outlook.

  1. Message-specific override
  2. Sender-address rule
  3. Sender-domain rule
  4. Automatic classifier result

Removing an override immediately reveals the current automatic assessment. Attention rules remain separate: a user may keep machine mail focused or leave likely-human mail quiet.

Do not overclaim
  • No “definitely human,” “AI-generated,” “safe,” “trusted,” or equivalent certainty claims.
  • No mailbox-, provider-, domain-, or thread-wide truth. Every message has its own result.
  • No destructive sweep. Any default-view hide is a reversible local disposition, never a provider mutation.
  • No live Microsoft OAuth dependency. Gmail, Outlook-normalized fixtures, and demo data are valid M5 verification inputs.

No stored evidence
unclassified · score null · insufficient_evidence. It is not silently downgraded to bulk merely because the old sync cannot reconstruct headers.
