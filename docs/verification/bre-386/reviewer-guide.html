The harness creates a fresh migrated SQLite database, authenticated sessions, two mail accounts for one user and an empty account for a different user. First visit → skip → reopen

  1. Open the reviewer session. Wait for the canonical preferences, View list and bounded all-mail read. The compact invitation appears in Inbox without stealing focus.
  2. Choose Skip for now; reload and open the second session. The automatic invitation stays hidden for this Orca user, including across its two provider accounts.
  3. Open Organization → Views → Getting started. Help reopens, keeps the stored timestamp and never creates or duplicates a View. Escape closes only help and returns focus to Getting started.
  4. Verify the independent empty user still sees their own invitation. No localStorage reset is needed.

Deleting the last saved View does not reset completion. The migration retires invitations for existing saved-View owners without mutating a GET request or replacing writing preferences.

Search mail → persisted View

  1. From invitation or Getting started, choose Search mail. The existing Search input receives focus.
  2. Search Project; inspect real results, then Save as View. General text remains an explicit unsupported clause.
  3. Explicitly replace it with subject contains Project. Inspect the real matching-conversation preview; Tune/refine/Undo remain the shared BRE-385 controls.
  4. Choose Save View. The returned stable View ID opens in My spaces; reload to verify the same canonical result.
  5. Inspect the scratch database result: exactly one saved definition and the human user's completion timestamp. No selected message IDs persist as membership.

Use selected mail → same workspace

  1. Choose Use selected mail. Existing selection mode opens once; returning to Inbox later does not replay that request. All Mail is used when the current Inbox has no selectable rows or the action starts in Organization.
  2. Choose real rows from one account. Activate Use these senders. Read the authoritative exact addresses and account before saving.
  3. Tune or correct, then Save. Cancel after edits must ask to discard; Keep editing retains the entire draft. Escape respects nested correction/Tune/discard behavior.
  4. Save and reload the canonical View. Getting started is outside active authoring and cannot replace its dirty draft.
