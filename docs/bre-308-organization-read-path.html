BRE-308 · reviewer guide · schema revision 1

One Organization seam. Thread truth. Explicit Account scope.

This slice replaces message-policy calls from REST and MCP with a provider-neutral Organization module. It exposes the complete five-operation interface, enables only describe and query, and keeps the existing inbox wire contract as a compatibility adapter.

Read path

ScopeActor · Workspace · Accounts
Organizationdescribe · query
AggregateThread organization
StorageSQLite adapter

Account fails closed

The module compares every claimed Account with live Workspace ownership, then verifies every query filter is a subset of that authorized scope. The SQLite adapter predicates all reads by Account.

Provider concepts stop at adapters

The Organization interface exposes Account, Thread, sender evidence, source IDs, and organization results. Gmail/Outlook names, OAuth scopes, tokens, and provider capabilities never enter its contract.

Thread owns meaning

Attention behavior and aggregate Human Signal are resolved once per Thread. Nested messages remain evidence and let the legacy inbox/search adapters preserve their current response shape.

Mutation stays off

simulate, apply, and revert exist at the seam but return operation_disabled. Send and provider deletion authority are explicitly false.

Single-user M8 reset strategy

BRE-308 requires no data reset. It adds no database table or migration. Existing Accounts, messages, labels, and Thread IDs remain intact; normal sync/push refreshes Thread aggregate facts through the new Organization-owned adapter.
  1. Defer the clean reset to the first mutating M8 schema. Lanes, Facets, Workflow State, Collections, Views, and Rules are intentionally absent here, so clearing speculative structures now would destroy working inbox customization without creating replacement truth.
  2. Use one versioned migration, once. In the pre-MVP single-user environment, that future migration may clear only organizational structures, seed the Fallback Lane and Workspace Schema revision, and rebuild every Thread organization projection.
  3. Preserve source mail. The reset must not delete users, oauth_accounts, threads, emails, provider tokens, labels, attachments, contacts, drafts, or delivery state.
  4. Keep it atomic and recoverable. Take the normal local SQLite backup, run the migration in one transaction, rebuild per Account, verify counts/isolation, then commit. Failure rolls back the reset.
  5. Do not dual-read. After that migration, all Organization callers use the new schema; rollback restores the pre-migration SQLite backup rather than maintaining two competing policy models.
