Unified Inbox classification API

BRE-250 · Human Inbox and Tideline are server-side views of the effective, per-message Human Signal result.

Request

GET /v1/inbox?view=:attention&classification=:classification&limit=:limit&cursor=:cursor

ParameterValuesMeaning
viewfocus, normal, quiet, hidden, allExisting attention filter. Omit it for the established default, which excludes quiet and hidden mail.
classificationhuman, tideline, uncertain, allOrthogonal effective-classification filter. Omit it for all.
limit1–100Page size.
cursorOpaqueContinue only with the same attention and classification filters. A cursor from another account set or filter returns 400 invalid_cursor.

Classification views

ViewEffective class included
Human Inbox · humanlikely_human
Tideline · tidelineautomated_or_bulk
Review · uncertainuncertain and historical unclassified rows
All mail · allEvery effective class
Attention and classification are independent. A likely-human message can be quiet; an automated message can be focused. Neither filter modifies mail at Gmail or Outlook.

Response guarantees

Each inbox row exposes humanClassification with automatic evidence, an optional user override, and the effective source, reasons, score, and classifier version. humanSignal mirrors the effective score when one exists. Counts are full account-scoped totals and are never derived from the current page. New clients that send classification receive separate counts.attention and counts.classification; callers that omit it retain the legacy top-level attention count shape during migration.

Thread detail preserves this same result for every message in messages[]. The existing thread-level attention.humanSignal remains a legacy reader aggregate only; it is not a thread classification and must not replace per-message results.
