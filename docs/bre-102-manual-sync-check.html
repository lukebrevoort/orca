BRE-102

Manual Gmail Sync Check

This walkthrough verifies the new first-page Gmail sync path, the protected manual trigger, and the SQLite rows written for messages, threads, labels, and contacts.

1. Verify Code
bun --filter @orca/api typecheck
bun --filter @orca/api test
bun --filter @orca/api db:verify
2. Start API
bun --filter @orca/api dev

Make sure your `.env` includes valid `SESSION_SECRET`, `TOKEN_ENCRYPTION_KEY`, `GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET`, and `GMAIL_REDIRECT_URI`.

3. Trigger Sync
curl -X POST \
  -H "Cookie: orca_session=<session-token>" \
  http://localhost:3000/v1/sync/gmail

Expected shape: `accountId`, `emailCount`, `threadCount`, `labelCount`, `contactCount`, `nextCursor`, `lastSyncedAt`.

4. Check DB
sqlite3 apps/api/data/orca.sqlite "
select count(*) from emails;
select count(*) from threads;
select count(*) from labels;
select count(*) from email_labels;
select count(*) from contacts;
select sync_cursor, last_synced_at
from oauth_accounts;
"

Re-running the same page should not increase duplicate message rows. `sync_cursor` should clear to `NULL` when the last page is consumed.

Acceptance
  • The sync endpoint returns 200 for an authenticated Gmail user.
  • Emails, threads, labels, and contacts are present in SQLite.
  • Duplicate reruns do not create extra `emails` rows.
  • `oauth_accounts.last_synced_at` updates after a successful sync page.
