Orca M6 · BRE-276 · architecture decision

The model stays outside. The boundary stays small.

For M6, model-assisted Reply Briefs live in a person’s external ChatGPT or Codex client. Orca exposes one explicitly selected thread through its existing OAuth-protected, read-only MCP resource. Orca holds no ChatGPT credential and invokes no OpenAI API.

Decision: external first, deterministic inside

Selected for M6: an external ChatGPT/Codex agent calls Orca’s read-only MCP resource after explicit user invocation. Model-assisted output stays outside Orca. Inside Orca, the only M6-compatible path is a bounded deterministic fallback that uses the same source-linked output contract and cannot draft, compose, send, or mutate provider state.

A future inside-Orca model runtime needs a separate decision and authorization covering API billing, credential ownership, retention, isolation, cost controls, and consent. A ChatGPT subscription is not OpenAI API credit.

Never part of a Reply Brief

  • Gmail/Outlook tokens, Orca sessions/cookies, MCP bearer or refresh tokens, ChatGPT credentials, OpenAI API keys, passwords, or authorization headers.
  • BCC, HTML, remote images, attachments, raw headers/provider payloads, provider message IDs, unrelated threads, unbounded history, or a mailbox corpus.
  • Calendar titles, descriptions, locations, attendees, organizer details, or event contents. Availability is free/busy intervals only.
  • draftText, replyBody, suggestedCopy, compose/send actions, or any provider write. Strict validation rejects unknown fields at every output level.

Explicit, one-thread data flow

1 · PersonSelects a message/thread and explicitly asks for guidance. No sync, push, background event, or email instruction can trigger a brief.
2 · External clientChatGPT/Codex presents an Orca grant and calls the existing read-only MCP surface. The client owns its ChatGPT/Codex credentials and model entitlement.
3 · Railway / OrcaValidates issuer, audience, scope, active grant, user, and live account ownership. It logs outcome metadata, never bearer material, prompt text, bodies, or model output.
4 · ProjectionAllowlist projection emits a bounded plain-text view of only the selected thread, marks mail untrusted, redacts secrets, and keeps model instructions outside email content.
5 · GuidanceThe external client produces source-linked guidance. If unavailable, disabled, limited, or declined, Orca’s deterministic fallback emits the same closed output shape without model egress.

Retention, logs, deletion, opt-out

  • Orca builds the context in request memory; it does not persist model prompts, context bundles, or model responses and creates no background queue.
  • Railway contains Orca’s existing normalized mail and MCP grant state. Operational logs record request ID, tool, user/grant identifiers, status, latency, byte counts, and redaction/truncation counts—not tokens, body text, prompt text, output, or calendar intervals.
  • The external client controls downstream model retention. Orca must say this before egress and cannot promise to delete a copy already handled by that client.
  • Disconnecting the client revokes its grant and refresh-token family immediately; live grant checks reject later access tokens. Deleting the Orca user cascades grants. Revocation blocks future access, not already exported content.
  • Feature default is off until connection and consent. Users can disconnect in Settings or choose the private fallback per request; no silent reconnection or continuous ingestion.

Credentials and failure behavior

Provider OAuthEncrypted at rest on Railway and used only by Orca’s existing read-only provider sync. Never forwarded to a model/client.
Orca MCP OAuthOrca issues short-lived access tokens; Railway stores grant state and hashed opaque refresh tokens. Rotation/replay and user revocation follow BRE-261/BRE-267.
ChatGPT/Codex OAuthOwned by the external client. Orca never receives, stores, rotates, or revokes it; Orca revokes only the Orca MCP grant.
OpenAI API keyAbsent in M6. No OPENAI_API_KEY, user key upload, API proxy, subscription lookup, or Railway model call. A future route must use separately authorized credentials and explicit billing.
FailureExpired/revoked/wrong-resource grants fail closed. Model outage, missing entitlement, timeout, malformed output, limit, or user opt-out produces no retry queue and no partial draft; use deterministic fallback or show unavailable.

Cost and rate limits

The external client owns model entitlement, billing, quotas, and model-side rate limits. Orca neither assumes a paid ChatGPT plan includes API usage nor pays for an M6 OpenAI API request.

Orca bounds MCP work to one selected thread and existing endpoint limits. A rate-limit response contains no message content. The client may offer a deliberate manual retry; Orca never retries in the background. The deterministic fallback has no model cost and remains bounded by the same input schema.

Threat notes

  • Prompt injection: message content is labeled untrusted; model instructions stay structurally separate; no write tool exists; message text cannot trigger another request.
  • Cross-account exposure: bearer account claims are intersected with current ownership on every MCP call; the context omits account identity.
  • Credential leakage: allowlist projection plus structural/lexical redaction; no sensitive logs; authorization headers never reach handlers or model input.
  • Overcollection: explicit selection, 25-message/20,000-character bounds, no background corpus, no attachments/HTML, and free/busy-only calendar data.
  • Output smuggling: a strict schema allows only guidance fields and rejects draft or action-shaped extras recursively.
