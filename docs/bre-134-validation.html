BRE-134 · reviewer guide

Gmail label migration

Verify that Orca offers a one-time, opt-in copy from user-created Gmail labels to Collections without changing Gmail.

Start the app

bun install
bun run db:migrate
bun run dev

Open http://localhost:5173/login, connect a Gmail account, and finish Google’s read-only OAuth flow.

Onboarding flow

  1. After OAuth returns to Orca, wait for the first sync to finish.
  2. Confirm the picker shows only user-created Gmail labels; Inbox, Sent, Drafts, and other system labels must be absent.
  3. Select two labels. Confirm the selected count, membership count, checkmarks, and Import selected action remain readable in both themes.
  4. Import. Confirm one Collection per selected label appears in the inbox sidebar and contains the matching current threads.
  5. Reload /onboarding. It should return to the inbox instead of repeating onboarding.

Skip and later import

  1. With a fresh connected account, choose Start clean. No Collections should be created.
  2. Open /settings/integrations/gmail or use Gmail labels in the sidebar.
  3. Import a label there and confirm it creates exactly one Collection.
  4. Reopen Settings and confirm the completion state; no duplicate Collection or membership should appear.

Read-only safety

Before and after import, compare the selected labels in Gmail. Their names, message memberships, and message data must be unchanged.

The API only reads normalized local label/message data and writes Orca migration, Collection, and Collection membership records.

Automated proof

bun run test
bun run typecheck
bun run build
bun run lint
bun run --cwd apps/api db:verify

The API test named imports selected Gmail labels once, supports skip, and handles accounts with no user labels covers selection, skip, no-label, later-import, and repeat-import behavior.
