BRE-318 · independent review

Scoped agents can organize Orca—without becoming mail providers.

This guide maps the five MCP Organization operations to the canonical Orca modules and gives reviewers a reproducible fixture-backed acceptance path. It is intentionally explicit about the negative space: no send, reply, forward, provider deletion, arbitrary code, or unscoped mailbox mutation exists in the tool catalog.

Architecture and authority mapping

OAuth bearer
Live user, client, resource, scope, and Account intersection.
Shared Zod edge
Actor, Workspace, Accounts, resource family, expected revision, typed target.
MCP adapter
Exactly describe, query, simulate, apply, revert for Organization.
Organization modules
Existing authority, compiler, evaluator, Views, Lanes, Facets, Contexts, Collections.
SQLite transaction
Rechecks ownership, capability binding, command digest, revisions, idempotency; appends Change Sets.

The explicit OrganizationAgentCapabilitySource is the trust seam. Human callers retain their existing behavior. Agent writes fail closed unless the authenticated adapter injects a live source; Context and Rule revision one-shot anchors carry that source to the transactional adapter for a fresh comparison.

High-value evidence locations

  • packages/shared/src/mcp-contract.ts — strict bounded inputs, typed apply union, approval and output schemas.
  • packages/shared/src/agent-contract.ts — exact tool catalog; separately filtered read-only catalog.
  • apps/api/src/agents/mcp.ts — OAuth/Account authorization, tool registration, structured results.
  • apps/api/src/index.ts — thin adapter composition over canonical Organization modules.
  • apps/api/src/organization/agent-capability.ts — explicit agent capability seam and discriminated actor guards.
  • apps/api/src/organization/rules/change-set-sqlite.ts — live MCP capability, durable approval binding, activation/revert.
  • apps/api/src/agents/mcp.test.ts — full five-operation fixture lifecycle and adversarial cases.
  • apps/api/src/auth/mcp/oauth.test.ts — truthful control consent and Account-scoped grant.

Independent-verifier focus

  1. Change the OAuth Account grant or Workspace ID and confirm every Organization operation fails before state changes.
  2. Replay activation after removing Account ownership or changing the acknowledged risk and confirm zero writes.
  3. Inspect organization_change_sets.command_json to confirm exact approval, Simulation ID, and risk are durable.
  4. Compare MCP query state after activation/revert with the REST Organization read path.
  5. Inspect tools/list and ensure apply/revert are non-read-only but non-destructive/idempotent, while the legacy read-only list contains neither.
