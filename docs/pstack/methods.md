# Supporting methods

These are local adaptations of engineering ideas, not separately registered upstream skills. The coverage matrix distinguishes methods from unsupported capabilities.

## Understand and design

For how/why/teach, trace entry point → data shape → boundary → observable effect; cite files and history, distinguish intent evidence from inference, and explain the result for the reader. Use only already authorized read-only sources; missing chat/history connectors remain gaps. For sharpen/in-your-own-words, restate the goal and measurable result without expanding scope. For architect/blast-radius, enumerate callers, invariants and alternatives, then execute the check that proves the key safety assumption.

## Implement and measure

For tdd, create a behavior-level failing regression before the fix when there is a cheap local test path, then prove the original trigger passes. For benchmark-checklist, record workload, limiter, production-equivalent settings, correctness/errors, alternating repetitions, spread and user-visible relevance. For typescript-best-practices and the architecture principles, model the domain with explicit types/state, validate external boundaries, keep internal logic simple, isolate mutable state, make retryable operations idempotent and migrate callers before deleting old APIs. Prefer subtraction and a small verifiable unit over speculative abstraction.

## Collaborate and explain

For swarm/arena, if authorized agents are available, assign disjoint ownership or isolated competing prototypes, use the same acceptance criteria, and consolidate evidence before selecting changes. Record actual capabilities; do not promise Cursor model routing. For unslop/technical-writing/no-comments, make prose concrete and remove narration that restates code while retaining necessary rationale, legal notices and safety explanations. For ketchup, summarize observed changes and decisions since the last checkpoint without inventing transcript history.

## Learn and sustain

For show-me-your-work/figure-it-out, maintain a local decision table with time, phase, decision, reason, evidence and result. Do not use the upstream logging executable. For reflect/correct, identify repeated evidenced failures, use the local encode-lessons-in-structure skill, and verify the resulting guard. For principles concerning autonomy, context and outcome, continue authorized reversible work in small checked units, summarize evidence and report genuine blockers. None grants permission for irreversible actions or external communications.
