User-defined mail destinations

Backend/shared foundation. A destination is a workspace-owned Organization identity, usable across connected accounts. The public API uses destination names and IDs; all writes pass through the existing Organization authority, audit, revision and transaction path. No frontend, provider write, alert delivery, preview, or production service changes are included.

One placement authority. The mailbox SQL, reader, and Organization queries resolve the same destination. Conversation choices reuse existing manual placement. Sender/account choices extend the same Organization transaction with typed binding actions.

Public contract

EndpointRequest / response
GET /v1/destinations{revision,fallbackDestinationId,legacyDestinationIds,destinations}. Workspace-wide list, ordered by position. Each entry includes id,isFallback,name,color,position,retiredAt,revision,notificationPreference,delivery,counts:{total,unread}. Counts are messages, including all attention behaviors. Filter retired entries from active pickers.
POST /v1/destinations{expectedRevision,name,color?}. Returns {state:catalog,destinationId}; use returned ID directly.
PATCH /v1/destinations/:id{expectedRevision,name?,color?,position?,notificationPreference?}. Returns same mutation result. Names trim and compare case-insensitively against active names. Position inserts into ordered list. Shared advanced notification policies require Organization editing.
POST /v1/destinations/:id/retire{expectedRevision,reassignToDestinationId}. Returns same mutation result. This first version only retires unreferenced non-fallback destinations. Referenced, legacy-mapped, or protected placements reject with a reason; update choices first. The endpoint does not automatically rewrite advanced rules or move mail.
GET /v1/destinations/routing?accountId=AOptional address or threadId; thread wins when both supplied. Returns the account's configured sender list/default and selected effective/inherited placement in one snapshot.
PUT /v1/destinations/routing?accountId=A{expectedRevision,target,destinationId:string|null}; null resets this scope to inheritance. Returns {state,undo}. Send Undo to the same URL without changing its revision.
GET /v1/inbox?destinationId=DExisting bounded mailbox endpoint. Destination filtering applies before counts and LIMIT. Supports existing account scope, classification, search and cursor. Destination selection includes all attention behaviors in that destination; old callers retain legacy behavior filtering.

Domain rows are visible but editable:false; the simple sender target edits exact addresses only. Reset sender entries are omitted from the configured list. Optional additive destination appears on inbox messages, reader messages, thread attention, and Organization lane placement. Original attentionBehavior fields remain legacy behavior metadata; use destination IDs for new placement UI.

Historic snapshots and cached catalogs receive the same read default. Color writes use the same revision, transaction and audit path as renames; omitted update colors preserve existing values. Space identity, account routing and placement remain unchanged.

Precedence and compatibility

  1. Safety lock preserves the actual visible destination when locked.
  2. Conversation manual placement, then unreset legacy conversation Inbox/Quiet override.
  3. Explicit sender destination, or an unsuperseded legacy exact sender choice.
  4. Advanced Organization rule/policy placement.
  5. Legacy domain behavior.
  6. Explicit account destination, or unsuperseded legacy account default.
  7. Workspace fallback.

Conversation destination resolution uses the latest stored sender, ordered by received time, created time, then message ID; all messages in that conversation share placement. A sender choice applies to current and future matching conversations within its account. There is no global address cache.

Null bindings are durable reset markers. They suppress the old explicit choice at that scope so reset actually reveals inheritance. New choices and resets supersede legacy placement at that scope; old Attention behavior data remains stored and readable. Legacy writes still invalidate new revision guards, but do not silently supersede a new binding. Undo restores the prior explicit destination or inherited state and rejects after any intervening relevant workspace mutation.

Initialization and durability

Migration 0042_custom_destinations.sql preserves existing fallback identity and name, including customized names. New workspace initialization names the newly provisioned stock fallback Inbox. Fresh users receive no fixed Focus/Quiet sidebar. Existing non-normal legacy references seed durable compatibility IDs; future legacy writes provision missing mappings on their write path. Name collisions with user destinations receive a distinct compatibility name. All GETs are read-only.

Bindings have workspace/account and workspace/destination foreign keys. Existing Organization action validation rejects missing/retired/foreign destinations and enforces capability and ownership checks. Retirement inspects references across the workspace, including accounts outside a selected mailbox. Mailbox revision triggers cover configuration, placement, bindings and legacy changes. Cursors also bind destination and account filters.

notificationPreference is notify|badge|quiet, backed by the destination's existing policy, independent of placement. delivery is always proposal_only. No notification delivery service is enabled.
