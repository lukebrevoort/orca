BRE-151 · Local review card

Upgrade permission.
Keep the inbox.

This flow must add only Gmail compose access, preserve the current OAuth account and sync cursor, and leave reading functional when consent is denied or the wrong Google account is chosen.

Setup

Start locally

  1. Run bun install.
  2. Configure .env from .env.example.
  3. In Google Auth Platform Data Access, add gmail.compose.
  4. Run bun run dev.
  5. Open http://localhost:5173/settings/integrations/gmail.
Baseline

Confirm read-only

  1. Connect a fresh test account from /login.
  2. Confirm Settings labels the account Read-only.
  3. Confirm Read inbox is Granted while Manage Gmail drafts and Send mail are Not granted.
  4. Open the inbox and confirm sync still works.
Upgrade

Grant deliberately

  1. Read the permission explanation in Settings.
  2. Choose Enable drafts and sending.
  3. Confirm Google requests Gmail draft/send access.
  4. Approve using the same Google account.
  5. Confirm Orca returns to the same page and all three capabilities read Granted.
Origin

Try from compose

  1. Open Compose and add a valid recipient.
  2. Choose Enable sending.
  3. Confirm Orca explains the scope before redirecting.
  4. Approve and confirm the draft is still present when Orca returns with Compose open.
Recovery

Deny safely

  1. Start the upgrade again and deny it in Google.
  2. Confirm Orca says Nothing changed.
  3. Return to the inbox and refresh.
  4. Confirm existing messages and sync remain usable.
Isolation

Choose the wrong account

  1. Start an upgrade for account A.
  2. Select account B in Google.
  3. Confirm Orca asks you to choose account A.
  4. Confirm no second account appears and account A remains read-capable.
Automated evidence

Run the safety suite

bun run typecheck · bun run test · bun run build

The OAuth tests cover minimum-scope construction, signed return paths, denial, identity isolation, capability merging, refresh-token preservation, and capability detection.
