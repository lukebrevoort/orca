01

What changed

REST and React remain adapters. Lane meaning, scope enforcement, precedence, revisions, idempotency, and audit evidence live behind the Organization module interface.

Stable destinations

Renaming, reordering, Policy changes, and retirement do not change a Lane ID. One active Lane is the Workspace Fallback.

Exactly one primary Lane

Migration backfills every Thread and SQLite provisions every future Thread through a foreign-keyed insert trigger. Unresolved outcomes follow the current Fallback.

Human precedence

Manual Override wins above Rules and Lane Policy. Safety Lock prevents subsequent placement changes until a human unlocks it.

Provider-safe retention

Policy supports visibility, interruption, review, and retention defaults. The wire contract and database both require providerDeletion: false.

02

Three decisive flows

Run the web app, then use these short journeys. Demo mode is deterministic and does not require credentials.

A · Create and configure a Lane

Open /dev/inbox?destination=organization→Enter a New Lane name→Create Lane→Rename or reorder→Change four Policy defaults
  1. Confirm the eight-character identity label stays unchanged after rename.
  2. Make another Lane the Fallback; exactly one control remains labeled Fallback.
  3. Confirm Retire Lane is disabled for the Fallback.

B · Override and protect a Thread

Open any Thread→Open Lane→Select Focus→Lock placement→Lane choices disable with readable labels
  1. The Thread header changes to the selected Lane immediately.
  2. Safety Lock reports “Locked by you.”
  3. Unlock restores Manual Override controls.

C · Explain placement

Open “Why is this here?”→Winning source→Precedence level→Actor→Reason + Account scope

The drawer never guesses. It renders authoritative fields returned by Organization query/apply and separately names an active Safety Lock.
