BRE-267 · M6 Agents

Read-only access,
held by a short leash.

ChatGPT and Codex connect to Orca as OAuth 2.1 public clients. The user chooses scopes and connected accounts, and can revoke one connection or every connection from Orca.

Implementation ready; feature remains default-off
1 · DiscoverResource + issuer metadata
2 · ConsentSession, scopes, accounts
3 · ExchangeCode + S256 PKCE
4 · VerifyClaims + live DB grant

What is granted

  • mail:read — bounded mail and thread reads.
  • agent_events:read — propagated agent-event reads.
  • Only explicitly checked, user-owned connected accounts.
  • No draft, send, archive, delete, relabel, or provider-write permission.

What is never stored

  • No OpenAI API key or ChatGPT credential.
  • No OAuth client secret; DCR clients are public and use PKCE.
  • No plaintext authorization code, access token, or refresh token in SQLite.
  • No provider access/refresh token is copied into an MCP grant.

mail:read maps only to the resource’s mail metadata, mail content, and connection-status read capabilities; agent_events:read maps only to agent-event reads. Every /mcp request rechecks the token hash, live connection, granted scopes, and current account ownership in SQLite.

Deployment and migration

  1. Apply apps/api/drizzle/0020_mcp_oauth.sql. It adds OAuth clients, single-use codes, connections, account grants, hashed access-token records, and rotating hashed refresh-token records.
  2. Use durable shared SQLite storage and the same versioned ORCA_M6_MCP_SIGNING_KEY on every API instance. It is separate from browser SESSION_SECRET; rotating the MCP key invalidates outstanding access tokens and pending consent requests.
  3. Set exact public HTTPS values for ORCA_M6_MCP_ISSUER and ORCA_M6_MCP_RESOURCE. The intended resource ends in /mcp.
  4. Leave ORCA_M6_MCP_ENABLED=false until the BRE-261 contract and BRE-265 MCP server are merged. Then enable it and restart the API.
ORCA_M6_MCP_ENABLED=true
ORCA_M6_MCP_ISSUER=https://api.example.com
ORCA_M6_MCP_RESOURCE=https://api.example.com/mcp
ORCA_M6_MCP_SIGNING_KEY=<base64-encoded-32-byte-key>
ORCA_M6_MCP_SIGNING_KEY_ID=mcp-v1

Retention and rollback guarantees

Code exchange and refresh rotation commit consumption plus every replacement credential in one SQLite transaction. Injected insert failures are tested to roll back the original credential. Opportunistic GC retains expired codes/access tokens for 24 hours, consumed refresh tokens for a 24-hour replay window, revoked connections for 30 days, and unused registrations for 24 hours.

Manual ChatGPT/Codex connection check

  1. Deploy the combined BRE-261 → BRE-265 → BRE-267 stack over HTTPS and enable the feature.
  2. Confirm both well-known endpoints return the same exact issuer/resource values and advertise S256.
  3. In the current ChatGPT/Codex plugin connection surface, add the Orca MCP URL from ORCA_M6_MCP_RESOURCE. For issuer-identifying servers like Orca, the current stable ChatGPT callback is https://chatgpt.com/connector_platform_oauth_redirect; use the exact redirect URI shown by the app management page if it differs. The client should dynamically register and open Orca consent—no API key field is involved.
  4. While signed into Orca, choose the requested read-only scopes and one or more connected accounts. Confirm the callback includes the original state and the exact issuer.
  5. Call one mail-read tool and one agent-event tool. A tool without its required scope must return 401 with WWW-Authenticate pointing to protected-resource metadata.
  6. Open Orca Settings → Agent connections. Confirm client, scopes, accounts, and last-used time. Check default, hover, focus, active, revoked, and disabled controls in light and dark mode.
  7. Revoke the connection, then repeat the MCP call. It must fail immediately; refresh must also fail. Reconnect, choose fewer accounts, and confirm inaccessible accounts never appear.
