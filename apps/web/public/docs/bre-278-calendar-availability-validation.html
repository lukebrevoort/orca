BRE-278 · Manual validation

Availability context,
without calendar access creep.

This guide verifies the provider-neutral contract, separate Google consent, selected-calendar scope, Free / Busy / Unknown comparison, and human-owned scheduling surface. Nothing here drafts a reply or changes a calendar.

Free/busy onlySeparate OAuth grantProvider-neutralHuman confirmsNo event writes

Visible fixture states

Free

No selected calendar overlaps the exact interpreted window. The original message timezone and checked-at time remain visible.

Busy

At least one selected calendar overlaps. Orca shows the scoped calendar result without exposing the event behind it.

Unknown

Ambiguity, stale data, a missing grant, an expired grant, or any selected-calendar failure never becomes “Free.”

Manual UI flow

  1. Start the fixtureRun bun run dev:web, then open http://localhost:5173/dev/reply-availability.
  2. Inspect the expanded Reply Brief contextConfirm the sender’s three requested windows, your timezone, original timezone, Free / Busy / Unknown labels, checked-at freshness, selected calendars, ambiguity, and source-message link are readable.
  3. Collapse and expand availabilityThe summary remains labeled in both states. Keyboard focus is visible. No draft, booking, accept, decline, invite, or send action appears.
  4. Verify both themesUse the sun/moon control. Check the default, hover, focus, and expanded states; labels stay readable in light and dark themes.
  5. Inspect selection controlsOpen http://localhost:5173/dev/calendar. Toggle Work and Focus blocks, working days, and timezone. Selected controls remain visibly labeled in both themes.
  6. Inspect consent recoveryOpen http://localhost:5173/dev/calendar?state=error. Confirm the disconnected state explains the separate Google consent, preserves the connect action, and shows an actionable server/callback message.
  7. Confirm human ownershipUse the information to decide what you would write. The surface says that you write and confirm; it contains no generated reply and changes no composer.

Screenshot evidence

Read-only boundary

  • Google Calendar authorization is incremental and independent from Gmail authorization.
  • Tokens are AES-GCM encrypted at rest and cleared on revocation.
  • Provider auth failures become Unknown; old results become Unknown/Stale.
  • Event titles, descriptions, attendees, locations, private notes, and raw provider responses never enter the contract.
  • The maximum Google FreeBusy query is 50 explicitly selected calendars.
  • No event create, update, delete, invite, RSVP, hold, negotiation, draft, or send capability is defined.
